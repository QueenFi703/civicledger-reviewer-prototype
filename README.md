# CivicLedger public reviewer edition

A browser-only, fictional demonstration of human-governed evidence review. It runs the real deterministic CivicLedger evidence engine, shows exact source lines, and lets a reviewer practice editing, accepting, rejecting, and inspecting a draft's temporary history.

[Open the public reviewer demo](https://civicledger-demo.queenfi24.chatgpt.site/)

**Do not enter real personal, financial, or medical information.** No sign-in, file uploads, live AI, paid connector, shared case database, or external sending is implemented. The application makes no case-data network requests. It loads ordinary static assets from its host. Optional official-resource links open third-party websites without case parameters or referrers; those websites have their own privacy practices.

## Run and verify

Requires Node.js 22.18 or newer and npm. Dependency versions are pinned and the lockfile uses the public npm registry.

```sh
npm ci --ignore-scripts
npm run check
npm run preview -- --port 4173
```

`npm run build` creates `dist/`. The production build is the supported reviewer preview. A restrictive HTML Content Security Policy uses `connect-src 'none'` and does not permit development websocket or inline React-refresh scripts. `npm run dev` is provided for engineering but production-preview validation should use `npm run build` then `npm run preview`.

Tests use Node's built-in TypeScript type-stripping support, not an additional test runner. `npm run check` runs the full tests, strict TypeScript check, ESLint, and production build. See [fresh public validation](qa/PUBLIC-VALIDATION.md) for what actually ran and remaining limits.

## Five-minute reviewer tour

1. Select **Seeded case** and run evidence checks. Both $1,800 and $2,100 remain unresolved; the $300 difference and missing September statement are explained.
2. Open a source chip. The viewer highlights the exact original lines, with page, version and SHA-256 reference identity.
3. Try **Gross / net mismatch** and **Different period**. The engine does not calculate an income difference for non-comparable records. Unreadable, missing-manifest, and partial-manifest fixtures do not produce a ready draft or invent absence findings.
4. Open **Clarification draft**. Review the references and acknowledge before accepting the demo draft. Add a fictional note, keep a new version, then reject it. An edit clears any earlier decision. Unsupported sentences are retained as unverified and acceptance stays blocked.
5. Inspect **Review record** for this tab's simulated events. Download optional labeled fictional JSON. Open **Sample assistant** for deterministic financial/support explanations and fixed public-resource references. No answer is generated by a model.

All nine fictional fixtures are available: seeded case, clean control, gross/net mismatch, different period, unreadable source, missing manifest, partial manifest, untrusted embedded instruction, and neutral name-equivalent control. The inert injection fixture includes a fabricated `SECRET-002` identifier and `example.invalid` URL as source text. Neither is followed or transmitted.

## Temporary state and limits

- Every app mount creates an independent in-memory session. No cookies, localStorage, sessionStorage, IndexedDB, service worker, or shared server store is used for reviews.
- The hosting service can set infrastructure cookies and process ordinary requests for static assets. This is not a claim that the hosting platform is cookie-free; application review text stays in the browser.
- Reload, a new tab, and **Reset demo** start with no runs or notes. A page restored through browser back/forward cache reloads to clear state. Changing the selected fixture does not delete prior runs in the same tab.
- Reset cancels pending operations and clears runs, notes, replay identifiers, and sample checks. Already downloaded JSON files remain on the user's device.
- Maximum 12 runs per tab, 100 events per run, 600 mutation request identifiers per session, 5,000 draft characters and 1,500 note characters. Reset starts again when a limit is reached.
- Returned data is deep-cloned. Source fingerprints, exact reference ranges, case IDs, draft versions and revisions are checked before acceptance. Concurrent changes and stale requests cannot silently replace newer versions. A reused request ID succeeds only for the same normalized payload and run.
- Accepting requires a source-ready packet, verified wording and explicit acknowledgment. Rejection requires a note. Neither action makes an eligibility or benefits decision or sends a message.
- These browser-side guards demonstrate workflow behavior. They are not authentication, trusted enforcement, or a durable/tamper-proof audit trail. A person controlling the browser can alter its code or memory.

## What differs from the private application

The deterministic engine, fictional fixture definitions, core types and engine regression tests are retained unchanged from the reviewed private v5 core. This edition replaces private authentication, API routes and database persistence with `src/demo-session.ts`. It removes live Astra/connector code and all private-service wiring, account details, deployment identifiers and project history.

The sample helper retains its deterministic behavior; an unused disabled-live class was removed, and a supplement label now says "temporary" instead of "saved". Its corresponding disabled-live test assertion was removed. The public UI and tests make no claim that the private database integration tests validate this new session implementation.

No working IBM watsonx or watsonx Orchestrate integration is included or claimed. No clinical, financial, eligibility, benefit-amount or fraud decision is made. The checklist is developer-authored synthetic material, not official program policy.

## Architecture and hosting

- `lib/civicledger/engine.ts`: extraction, comparisons, exact reference validation and conservative draft verification.
- `lib/civicledger/fixtures.ts`: nine fictional fixture variants and synthetic checklist.
- `lib/civicledger/astra-preview.ts`: preset deterministic sample explanations with validated references.
- `src/demo-session.ts`: disposable review state with version/replay/race/reset guards.
- `src/workspace.tsx` and `src/sample-panel.tsx`: accessible reviewer interface and exact source viewers.

Deploy only `dist/` to a static HTTPS host. No environment variables, backend, user accounts, database binding or private project configuration is required. Relative asset paths support a repository subdirectory. Configure the host to serve `index.html` and static assets, and retain the built HTML CSP. Add an HTTP `Content-Security-Policy: frame-ancestors 'none'` header if the host supports it. Publish the source separately from build output and record the public commit and artifact hashes at deployment. Do not copy private deployment configuration.
